# 📒 주식가계부

매수·매도를 **매입 단가별로** 기록하고, 매도할 때 평균단가가 아니라
**가장 유리한 매입건부터 매칭**해 실현손익을 계산하는 개인용 주식 장부 모바일 웹.

```
npm install
npm start        # http://localhost:3100
```

## 핵심 계산 규칙

일반적인 증권 앱은 평균단가로 손익을 계산하지만, 이 앱은 **남아있는 매입건(lot) 중
단가가 가장 낮은 것부터 소진**한다.

- 이익이 나는 매입건이 최대한 먼저 반영된다.
- 매도가가 모든 매입가보다 낮아 전부 손실인 상황에서도, 손실이 가장 작은 건이 먼저
  나가므로 **손실이 최소화**된다.
- 동일 단가끼리는 먼저 산 것부터 나간다.

계산 로직은 `lib/match.js` 한 파일에 모여 있다. 선입선출(FIFO)로 바꾸고 싶으면
`matchSell()` 의 정렬 기준만 고치면 된다.

## 로그인

아이디·비밀번호로 가입해서 쓴다. 사용자마다 자기 종목·거래만 보이고, 남의 자료는
API 레벨에서 막힌다.

- 비밀번호는 scrypt 로 해시해 저장한다 (평문 저장 없음).
- 세션은 DB 에 두므로 서버가 여러 대여도, 서버리스로 배포해도 그대로 동작한다.
- 비밀번호를 바꾸면 지금 쓰는 기기만 남고 다른 기기 로그인은 모두 끊긴다.
- 로그인·가입 시도는 IP 당 분당 10회로 제한된다.

**공개 배포 시 가입 제한** — `SIGNUP_CODE` 환경변수를 넣어두면, 그 코드를 아는 사람만
가입할 수 있다. 넣지 않으면 누구나 가입할 수 있으니 공개 주소로 쓸 때는 설정을 권한다.

## 화면

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 로그인·회원가입 | `/login.html` | 첫 실행이면 회원가입 화면부터 열린다 |
| 포트폴리오 홈 | `/` | 보유 종목별 수량·평균매입가·누적 실현손익 |
| 종목 상세 | `/stock.html?id=` | 매입가별 잔여수량 · 거래 내역(어느 매입건에서 매칭됐는지 표시) |
| 거래 추가 | `/add.html?stockId=` | 매수/매도 · 토스 캡처 첨부 또는 직접 입력 |
| 매도 시뮬레이션 | `/simulate.html?stockId=` | "3주를 180만원에 팔면?" 실현손익·매도 후 보유현황 미리보기 |

매도 시뮬레이션은 **총 매도금액 / 주당 단가** 어느 쪽으로 입력해도 되고, 나머지 값은
자동으로 환산해 보여준다. 저장은 하지 않는 미리보기다.

## 캡처로 거래 등록

토스 **주문 내역** 화면을 캡처해 올리면 거래를 자동으로 읽어 채운다. 한 장에
매수(구매)와 매도(판매)가 섞여 있어도 그대로 인식한다.

토스 화면은 날짜가 행마다가 아니라 **그룹 머리글로 한 번만** 찍히기 때문에
(`7.31` 아래에 판매 2건이 묶이는 식), 캡처를 두 번 훑는다.

1. 한국어 전체 인식 → `판매/구매 N주`, `주당 N원` 줄과 각 줄의 세로 위치
2. 왼쪽 날짜 열만 숫자로 인식 → 날짜와 세로 위치

두 결과를 세로 위치로 맞물려 어느 날짜에 속한 거래인지 정한다. 연도는 화면에
없으므로 오늘을 기준으로 채우고, 미래가 되면 작년 것으로 본다.

읽어온 값은 **저장 전에 확인·수정하는 화면**을 거친다. 숫자가 잘못 읽히면 손익이
틀어지므로 바로 저장하지 않는다. 저장할 때는 날짜가 이른 것부터, 같은 날이면 매수를
먼저 처리해 매도가 그 시점의 보유분과 맞물리게 한다. 보유 수량이 모자란 매도처럼
저장할 수 없는 행은 사유와 함께 화면에 남는다.

캡처 원본은 등록된 거래에 증빙으로 함께 보관된다.

## 기술

Node.js 20+ · Express · libSQL(SQLite) · 프레임워크 없는 바닐라 JS 프런트엔드.

```
lib/db.js       스키마 + 질의 래퍼
lib/auth.js     비밀번호 해시 · 세션 · 로그인 미들웨어
lib/ocr.js      토스 캡처 판독 (tesseract.js)
lib/match.js    매도 매칭 엔진 (핵심 로직)
routes/auth.js  로그인 · 회원가입
routes/api.js   REST API (전부 로그인 필요)
public/         화면 (HTML/CSS/JS)
```

거래 캡처 이미지는 파일시스템이 아니라 DB(`screenshots` 테이블)에 담기므로,
파일 쓰기가 안 되는 서버리스 환경에도 그대로 올라간다.

## 배포하기

### 로컬 / 개인 서버

```
npm install
npm start
```

자료는 `data/stock.db` 파일 하나에 저장된다. 이 파일만 백업하면 된다.
디스크가 유지되는 곳(Render, Railway, Fly.io, 집 PC 등)이면 이대로 배포하면 된다.

### Vercel (서버리스)

서버리스는 파일 저장이 안 되므로 DB 를 [Turso](https://turso.tech) 로 옮긴다.

1. Turso 에서 DB 를 만들고 접속 URL 과 토큰을 받는다.
   ```
   turso db create stock-ledger
   turso db show stock-ledger --url
   turso db tokens create stock-ledger
   ```
2. Vercel 프로젝트에 환경변수를 넣는다.

   | 이름 | 값 | 필수 |
   |---|---|---|
   | `TURSO_DATABASE_URL` | `libsql://...` | ✅ |
   | `TURSO_AUTH_TOKEN` | 위에서 만든 토큰 | ✅ |
   | `SIGNUP_CODE` | 가입에 필요한 코드 | 선택 (공개 주소면 권장) |

3. 배포한다. 테이블은 첫 요청 때 자동으로 만들어진다.

> 캡처 판독은 글꼴 학습 데이터(약 7MB)를 처음 한 번 내려받는다. 서버리스는 인스턴스가
> 새로 뜰 때마다 다시 받으므로 첫 판독이 느릴 수 있다. 캡처 등록을 자주 쓴다면 디스크가
> 유지되는 곳(Render, Railway 등)이 낫다.

환경변수가 없는 채로 배포하면 앱이 동작하지 않고 설정 안내 메시지만 응답한다.

> ⚠️ 공개 주소로 배포한다면 `SIGNUP_CODE` 를 설정해 아무나 가입하지 못하게 막고,
> HTTPS 로 서비스하자 (세션 쿠키가 HTTPS 에서만 `Secure` 로 전송된다).
